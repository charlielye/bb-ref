# Performance vs barretenberg

**Goal: at parity or better with bb in proving time, memory, and wasm module size**, measured
against stock bb at the pin ([`tools/PIN`](../tools/PIN)), with every proof byte-identical to
bb's. This page records where bb-ref stands against that goal, how to reproduce the numbers, which
optimizations own them and where they live in the code, and what was tried and rejected. The raw,
chronological record (every measurement, retraction and dead end) is
[`bench-results/LADDER.md`](../bench-results/LADDER.md); this file is the curated view.

No optimization here changes an output bit: each was gated on byte-identical seeded proofs against
bb and the full test suite.

Under V8, the browser-relevant shape, bb-ref uses less memory on every flow.

**wasm module size** (the browser download; bb-ref.js's module against bb.js-api's threads module,
as the [bench page](https://charlielye.github.io/bb-ref/) serves them, gzip -9):

| module | raw | gzipped |
|---|---|---|

| **bb-ref** (`bb-ref-threads.wasm`: Chonk-only, stripped) | **8.63 MB** | **2.12 MB** |

The bb-ref.js modules are built with `--cfg chonk_only` (the Ultra commands answer unsupported) and
`-C link-arg=--strip-all` (no name section). The CLI module `tools/bench_tables.sh` benchmarks is
the full prover (Ultra, rollup, Chonk) and is larger; it proves identically. Native binary size is
not compared: a trivial invocation costs the same few milliseconds for both.

Reading the ratios: bb's wall includes a self-verify that ours does not, and bb's release wasm
module carries a ~100 MB name section that costs it ~2% of wall in load, so the wasm tables take
bb's wall from a *stripped* module and bb's proving-only from an `ENABLE_WASM_BENCH` module.
**Proving-only is the metric that compares the provers**; wall is what a user sees. Memory under
V8 is the final linear-memory size (it only grows), the browser-relevant number.

## Reproducing

**Reference machine: bbbench**, a 16-core AMD EPYC 9R14 (Zen 4, AVX-512 IFMA, no SMT, two 8-core
L3 domains). Both provers seeded (`BB_RNG_SEED=12345`), 8 threads for client flows, 16 for the
rollup corpus, nothing pinned to cores. Kernel-level decisions (especially wasm) must be measured
there: a Zen 3 workstation once called a 7.7% win ~1%.

**Builds.**

- *Native:* `cargo build --release`. `.cargo/config.toml` adds `+bmi2,+adx` (ark-ff's asm and
  bb-ref's ADX field, below) and `-inline-threshold=1000` (stock ark-ff's `#[inline]` wrappers are
  otherwise outlined, ~5% of native proving).
- *wasm:* `cargo build --profile lto --target wasm32-wasip1-threads` (`[profile.lto]`: opt-level 3,
  fat LTO, one codegen unit; the default release profile stays opt-level 2 for iteration).
  `.cargo/config.toml` adds `+simd128`, 4 GiB max memory, and inline memcpy/memset expansion up to
  48 stores. **Never set `RUSTFLAGS` for a wasm build**: it silently replaces that list.
  `tools/wasm_check.sh` fails a module built without it (by its `memory.copy` count).
- *wasm, wide arithmetic:* the same build with `--cfg wasm_wide` and `+wide-arithmetic`, the full
  flag list restated in `RUSTFLAGS` under its own `CARGO_TARGET_DIR` (see `tools/bench_tables.sh`
  or `tools/build_bb_ref_js.sh`). Needs an engine with the wide-arithmetic proposal.
- *bb-ref.js:* `tools/build_bb_ref_js.sh` builds the library as a wasi reactor `cdylib` (`ffi`
  feature) in both forms, Chonk-only and stripped, and generates the TypeScript package from the
  pin's ipc-codegen.

**Benchmarks.**

| tool | what |
|---|---|
| `tools/bench_tables.sh [table ...]` | the tables of record (`native`, `v8`, `wasmtime`, `v8-wide`, `rollup`): builds locally, runs on `$BENCH_HOST` under `flock ~/bench.lock`, copies the tables back |
| `tools/bench_chonk.sh [flow ...] [--threads n] [--reps n]` | native chonk, bb vs bb-ref: wall, proving-only, peak RSS |
| `tools/bench_chonk_wasm.sh v8\|wasmtime [flow ...]` | the same under node (`tools/runwasi_threads.mjs`, worker threads + shared memory) or wasmtime; `BB_WASM`, `BB_WASM_BENCH`, `REF_WASM`, `NODE`, `REPS` |
| `tools/bench.sh <corpus> --pair <bb> <bb-ref>` | the rollup corpus replayed frame by frame |
| `tools/ab_chonk.sh name=path ...` | interleaved A/B on the bench box: paired median, win count, and every non-bb proof checked against single-threaded bb goldens |
| `tools/remote_bench.sh [host] [msm ...]` | quick gates (one chonk flow, one rollup frame) and the MSM rung |
| `js/chonk-bench` | the browser page (`serve.mjs`; `build-site.mjs --publish` for GitHub Pages; `run-node.mjs` for the same packages under node), bb-ref.js against bb.js-api on the pinned flows |
| `tools/wasm_p0/` | wasm phase, memory and profile analysers |

**Instrumentation.** bb's `--print_bench`/`--bench_out` (`BB_BENCH`) against bb-ref's
`BBREF_BENCH=1` (`src/base/bench.rs`), with bb's scope names. Finer probes: `BBREF_ROUND_DETAIL=1`
(per-round breakdown of the sumcheck univariate), `BBREF_TIMING_RELATIONS=1` (time and active edges
per relation),
`BBREF_MSM_TIMING`, `BBREF_COMMIT_TIMING`. A/B switches on one binary: `BBREF_NO_IFMA=1`,
`BBREF_DEDUP=0`, `BBREF_GLV_LOG2`, `BBREF_TINY_MSM_MAX`. Heap profile: `--features heap-profile`
(dhat), aggregated by `tools/heap_agg.py`.

## Benchmarking traps (each cost real time at least once)

- **bb's seeded chonk proof is not deterministic above one thread** (its parallel random-polynomial
  draws race on the engine); bb-ref's is, and equals single-threaded bb's. Gate on
  single-threaded goldens.
- **bb's reported scope `time` is the largest single thread's total (`time_max`), not a sum.**
  Summing our per-thread times against it once produced a phantom "MSM is 2.6×".
- **Scope boundaries differ; reconcile before comparing.** bb's `OinkProver::prove` includes the
  hiding kernel's oink (ours is a separate scope); bb's `create_circuit` excludes witness decode;
  bb's `acir::recursion_constraints` and `Chonk::complete_kernel_circuit_logic` are siblings where
  ours is one scope; our `TripleIPA` includes claim reduction that bb's
  `IPA::compute_opening_proof` does not. Non-overlapping top-level scopes must sum to ~90–96% of
  wall on both sides or the table is wrong.
- **Never phase-measure wasm under `--no-liftoff`.** TurboFan compile time lands on whichever phase
  first calls each function, favouring the smaller module (it once inverted a result). Plain
  `node` (Liftoff + dynamic tiering) is the production shape.
- **Compare against a stripped bb wasm module** for wall (`tools/wasm_p0/wasm_strip.py`), or quote
  proving-only.
- **wasm runners must create memory at the module's declared minimum.** A runner that created
  1,200 initial pages added ~73 MiB to every reported peak.
- **`RUSTFLAGS` replaces `.cargo/config.toml`'s target flags** (see Builds).
- **Noise.** Flows vary ~2–3% run to run, the sumcheck round rung ~6%, bb's MSM bench more; wasm
  peak memory on storage_proof ±30 MiB. Nothing under ~10% can be called from single or paired
  samples: use `tools/ab_chonk.sh` (n ≥ 5 interleaved reps, paired median and win count). Several
  "wins" evaporated under that test.
- **A suspiciously large win is usually a panic or a stale binary.** Check for `Finished`, abort on
  `error`, verify the proof bytes.
- **Concurrent A/Bs must not share remote binary names** (`ab_chonk.sh` content-addresses them);
  `pkill -f`/`pgrep -f` match their own command line over ssh; check the box's load average before
  trusting a number.
- **Worker-thread `eprintln!` is not captured by the harness**; accumulate and print from main.
- **bb's per-op rollup numbers swing ±20% with allocator warmth.** Use the warm marginal wall or
  `perf stat` instruction counts.
- **Instruction counts and wall diverge**, and sampling profilers mis-attribute parallel cost. Use
  hardware counters for parallel efficiency, and measure rather than scale old numbers.
- **`ECCVMShort/loop_static_blocks` in bb's sumcheck bench is round 0 only.**

## Where the speed comes from

By area, with the code that owns it. Most items are bb's algorithm ported; many recent ones are
ports of the [chonk-golf](https://github.com/olehmisar/chonk-golf) patch series (cited as
"golf NNNN" in the source).

### Field arithmetic (`src/base/field.rs`, `src/base/wasm/`)

- **Native x86-64 (`wasm/adx.rs`):** bb-ref's own `MontConfig` for bn254 Fr/Fq with arkworks'
  constants and stored form, and bb's lower-latency ADX multiply and square (golf 0036; mul
  20.3 → 16.1 ns), branchless asm add/sub/double. Other native targets use arkworks' configs.
- **Inversion:** bb's Bernstein–Yang safegcd (`divsteps.rs`, shared; 62 divsteps per matrix on
  x86-64 in `adx.rs`, 58 on nine 29-bit limbs on wasm in `by29.rs`), ~3.5× arkworks' binary EEA.
- **wasm (`wasm/field.rs`, `mont29.rs`):** bb's 9×29-bit Montgomery multiply (every partial product
  one `i64.mul`, Karatsuba 5+4), in bb's 2^261 stored domain, always inlined. The 2^261 domain is
  carried by four constants in `field.rs` (`R2 = 2^517 mod p` makes arkworks' const constructor and
  `MontFp!` land in it), so arkworks' `Fp` container is used unpatched. The wasm prover is
  mul-bound: this kernel was the first tier of all wasm work.
- **wasm, wide arithmetic (`wasm/wide.rs`, `--cfg wasm_wide`):** a 4×64 no-carry CIOS over `u128`
  products lowered to `i64.mul_wide_u`/`i64.add128`, in arkworks' 2^256 domain, replacing the
  2^261 field and its four-lane kernels; `widepacked.rs` and `widetree.rs` are its raw-limb
  streaming and MSM-tree loops.
- **SIMD:** `wasm/quad261.rs` is bb's multiply as a four-lane simd128 kernel (`VectorField`), used
  by the streaming polynomial ops (`packed.rs`), the MSM tree drain (`tree.rs`), the IPA SRS fold
  (`ipafold.rs`) and the permutation relation (`perm4.rs`). Natively, `src/base/ifma.rs` is
  AVX-512 IFMA (eight lanes of five 52-bit limbs, golf 0031), runtime-dispatched, for the MSM
  drain, sumcheck folds, `add_scaled_batch`, the IPA fold and the permutation relation.
  `wasm/fallback.rs` gives every other target the same names answering "no packed form".
- Canonical bytes decode to field elements in one Montgomery multiply (ACIR constants and witnesses
  straight to Fr); batched inversions serial in place for small batches, element-parallel
  (`batch_invert_par`) for the large denominators.

### MSM and commitments (`src/base/msm.rs`, `src/base/srs.rs`, `src/base/fold.rs`, `src/base/endo.rs`)

- **Batched-affine Pippenger in the shape of bb's `scalar_multiplication_fast`**, stage by stage:
  signed Booth digits, per-scalar MSB profile with rounds sized to the bit length, counting-sort
  schedules, pair-tree reduction through one shared inversion per level, `recursive_affine_bucket_reduce`.
  Unlike bb's unsafe path it handles equal, inverse and infinity pairs exactly, so verifier-side
  batch muls use it too.
- **GLV only below a threshold** (bb's `GLV_SMALL_N_THRESHOLD`; `MSM_DEFAULT_LOG2` in
  `wasm/mod.rs`: 2^16 on wasm, 2^12 natively, measured for this code) and never for scalars of
  ≤128 bits. The φ(SRS) companion table is precomputed only on wasm and only up to the threshold,
  and its lazy build never blocks (a commit finding it unbuilt runs without it: this fixed a rare
  rayon deadlock).
- **Stage-6a subchunk** 4096 on wasm (one inversion per tree level amortized; ~130 muls each), 2048
  natively (4096 raised RSS). Gather prefetch natively; structure-of-arrays tree.
- **Small MSMs:** sparse inputs compact to their support; MSMs of ≤128 points use width-5 wNAF over
  one shared doubling chain (`tiny_msm_wnaf`).
- **Duplicate-scalar pre-pass** (bb's Phase A dedup, `Ck::commit_dedup`): witness wires are ~50%
  repeated scalars; equal scalars are summed once (batched-affine clusters) and the MSM runs over
  the distinct ones. Gated on a sample of the polynomial.
- **Bounded scratch:** `batch_commit` caps in-flight MSM scratch at bb's 32 MiB budget; scratch
  freed at last use. The Montgomery-form SRS is cached on disk (`bn254_g1.ark.mont` in `$CRS_PATH`, default `~/.bb-crs`).
- **IPA SRS fold two rounds at a time** (bb `batch_two_round_fold`, `fold.rs`) on one shared
  doubling chain with the `u1·u2` product GLV-split; packed on wasm (`ipafold.rs`), IFMA natively.
- The op queue sums its `mul_accumulate` terms as one MSM at `eq_and_reset`.

### Sumcheck (`src/honk/sumcheck.rs`, `src/honk/graded.rs`, `src/honk/relations.rs`)

- Row skipping (`witness_end`, bb's `end_index`, halved per round), relation skipping, partial-length
  evaluation, precomputed barycentric weights, lazily filled edge rows.
- **Coefficient-basis relation evaluation** (`Graded<F>`, bb `UnivariateCoefficientBasis`): edge
  rows are degree-tracked `row0 + X·Δ`, so each ring operation costs its true degree; Karatsuba
  short products, free ±1 constants, linear×longer Karatsuba. A wide (24) variant serves the
  ECCVM's high-degree set and lookup relations; the Translator's add-heavy relations keep the
  pointwise path.
- **Coefficient-form batching across relations** (what bb's `USE_SHORT_MONOMIALS` buys): the batched
  round polynomial is formed in coefficient form and evaluated once.
- **Prover-only shortcuts behind `FieldLike::IS_PROVER`** (false for circuit witnesses, so the
  recursive verifier's gates and the VKs are untouched): balanced products in the Permutation
  relation (bb's `IsProverAccumulator` split), identical-pair fold skip, databus column skip,
  `q_arith == 1` path, memory-relation gate-type skip, Poseidon2 separator folding.
- **Permutation relation on edge lanes** (`PERM_LANES`): four edges per simd128 op on wasm
  (`perm4.rs`), eight IFMA lanes natively; the relation owns most of the folding sumcheck's multiplies.
- **One parallel dispatch per round**, per-worker scratch, rounds of ≤8 edges on the calling thread,
  edge prefetch two ahead, first fold reading each column as one slice.
- **Memory:** owned round tables skip each column's leading zeros; the joint MegaZK+Translator
  sumcheck materializes its tables after round 1 at quarter size.
- Translator: edges where `op` is zero at both ends are skipped (no-op padding is ~93% of a small
  flow's op queue), and the ZeroConstraints relation takes bb's skip.

### Prover phases and builder

- Multilinear batching on each claim's support with the eq table factored; Gemini evaluation and
  folds parallel; Shplonk/KZG quotients parallel; zero/unit skips in `add_scaled_batch`.
- Prover instance: sigma/id and copy cycles parallel, grand product blocked-parallel (bb's
  steps 1–3); ECCVM row tables built concurrently, transcript scalar muls parallel, zero-tail
  extension for the grand product and lookup inverses; SmallSubgroupIPA parallel.
- Builder: cached sha256 sparse-form powers, powers-of-two table for limbed range constraints,
  bigfield in fixed-width accumulators, keccak ρ on base-11 digits, fewer Montgomery conversions.
- **Lifetimes:** each step's program decoded just before it is accumulated; builder slack freed
  before the wires are written; folded instances store gate selectors from their first block
  (`Polynomial::start`, bb's `start_index`); the folded instance freed before multilinear
  batching, joint sumcheck tables before the joint PCS, the final accumulator after the decider.
- **`--prebuild`** (opt-in, `bb-ref prove --scheme chonk ... --prebuild`): the next circuit is built
  on a helper thread during accumulation, with all randomness still drawn on the main thread in
  order. Trades up to one extra builder of memory for wall; not used in the tables of record.

### Allocator and runtime

- **Native: transparent huge pages** via `glibc.malloc.hugetlb=1`, self-applied by one re-exec at
  startup (`apply_hugepage_tunable` in `src/bin/bb-ref.rs`; a hand-set value wins). On 4 KB pages
  the prover's multi-megabyte short-lived buffers cost millions of refaults. With it the system
  allocator matches mimalloc's speed at about half its RSS; mimalloc remains an A/B feature
  (`--features mimalloc`).
- **wasm: `src/base/wasm/alloc.rs`**, a correctness fix. V8 bounds-checks `memory.fill`/`memory.copy`
  against a per-thread cached memory size that another thread's `memory.grow` updates only
  asynchronously, so memsetting freshly grown pages can trap "out of bounds". Every heap op
  refreshes the thread's view with `memory.grow(0)` when needed. `examples/growstress.rs` under
  `tools/runwasi_threads.mjs` is the regression test.

## Tried and rejected

Measured and not adopted; do not retry without the stated new evidence. Details in LADDER.

| attempt | result / why | retest if |
|---|---|---|
| Packed SIMD for the whole sumcheck plane (4-wide `QuadF` edges) | 1.8× slower on the dense round-0 rung; bb's own SIMD sumcheck worth 2.7% and gated off on skip-heavy traces. Scoped to the permutation relation it paid (above); the lookup relation on 4-lane batches did not (+0.6–1.1%) | — |
| Fused wasm multiply variants, golf's 5-wide kernel shape, Rust reorderings of the 4-lane multiply | none faster; V8 codegen-bound; wasm `extmul` needs lane shuffles on x86 | on ARM, where `extmul` maps to NEON (every SIMD number here is x86) |
| f64/FMA wasm field multiply | bit-exact, but ties at stored-form boundaries and +46% at scalar sites; needs relaxed SIMD, which Safari lacks | — |
| bb's C++ `VectorField` drains linked into the module (`bbkernel`) | worth 7.7% of wasm proving on Zen 4 under production tiering (clang's barrier-pinned instruction order in V8's baseline tier); removed as C code in the repo | owner decision on C code |
| Fused `sum_of_products` (native) | slower; less ILP than two independent multiplies and it forfeits the zero-coefficient skip | — |
| LTO / `codegen-units=1` natively; `opt-level = 3` for the default profile | flat; the native outlining was the `#[inline]` layers (now `-inline-threshold=1000`) | — |
| `wasm-opt -O3` | module smaller but +11% slower on the flow | newer binaryen/V8, or `-Os` if size ever binds |
| Porting bb's `parallel_for_mutex_pool`; bypassing rayon; spin-before-sleep | neutral; dispatch is ~25 µs/round, the deficit was our own serial tail | profile showing work-stealing spin under saturation |
| A dozen sumcheck round-loop shapes (striping, persistent state, row-parallel fold, chunk divisors, …) | all neutral or worse on paired tests | — |
| Parallel `batch_over_relations` | a second barrier per round costs more than the work | — (coefficient-form batching removed the work) |
| `GRADED_MAX_LEN` 8 → 9; hybrid coefficient/evaluation `Graded` (bb's representation dynamically); six `Graded` copy-traffic variants | taxes every flavor / slower on every relation / neutral; bb's version is statically sized, which stable Rust cannot express | `generic_const_exprs` stabilizing |
| Re-associating Permutation products unconditionally | pinned VKs no longer match (bodies are shared with the in-circuit verifier) | — (resolved by `IS_PROVER`) |
| MSM structure variants (pack-on-push, copy elision, bucket packing, index staging, sort-based dedup, tiled scatter, 64-byte gather, window ±1, fewer concurrent MSMs, single-threaded small MSMs) | neutral or flow-negative; the tree's cost is the field math both provers pay | a rung isolating bookkeeping with a >10% item |
| Bigger memory-for-speed trades: SRS precompute tables, full φ table, uncapped `batch_commit`, late tables in every sumcheck, a 16 MiB MSM budget | small wins for hundreds of MB, or none | a long-lived prover where memory is cheap |
| bb-style caching allocator; `talc` on wasm; cutting allocation churn under mimalloc | slower or no effect; page size was the lever | — |
| Small-value sumcheck rounds | 85% of values are full-size | — |
| Thread / L3-domain pinning | not controllable in production | — |

## Protocol-changing ideas (upstream proposals, not bb-ref changes)

These would change proofs or the verifier, so they belong in bb: GKR-based grand products and
lookups (LogUp-GKR) in place of the committed `z_perm` and inverse polynomials; a dynamic ECCVM
size (small flows use ~3,000 of its 32,768 rows; the ECCVM + translator tail is mostly fixed cost);
deferring the Grumpkin IPA opening to the rollup; lower-degree restructuring of the highest-degree
relations (ECCVM `Set` at 22, Poseidon2 internals); tighter structured-trace block capacities.

## History

Until 2026-10 the reference included a second bb, the pinned bb plus the
[chonk-golf](https://github.com/olehmisar/chonk-golf) patch series (~0.53× stock bb natively), used
as a temporary state-of-the-art target; bb-ref reached and passed it on native, wasm time and wasm
memory (LADDER Updates 66–70; the `chonk-golf-*.txt` tables in git history). The headline now compares against
stock bb only. The earlier arc (from 1.34× bb on wasm to parity, the ark-ff fork and its
retirement, the removal of the C kernels) is in LADDER Updates 1–65.
